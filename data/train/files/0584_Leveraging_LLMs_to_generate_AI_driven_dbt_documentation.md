Introduction
In the ever-evolving landscape of analytics engineering, finding ways to streamline workflows and increase productivity is paramount. One powerful tool that can help achieve this is Large Language Models (LLMs). Harnessing the capabilities of LLMs empowers us to automate labor-intensive tasks such as documentation, freeing up valuable time for Analytics Engineers to focus on more complex and strategic endeavors. In this article, we will delve into the practical applications of LLMs in the analytics engineering realm, exploring how they can revolutionize workflows and enhance overall efficiency.
Background
The open-source Extract-Load-Transform (ELT) framework we use across the data organization at Loblaw Digital is dbt. A model serves as an essential building block of a dbt framework. Models usually reside in a single file and contain logic that transforms data. This logic can be expressed as a SQL select statement or a Python dataframe operation. Out of the box, dbt allows us to generate a static documentation website that lists all available models across different projects or folders, detailed information like its dependent models, as well as which other models reference it, and finally a lineage graph.
Each dbt model consists of an SQL file that transforms data and a corresponding config file that contains the schema information, such as a brief description of what the model does, columns that are available, and the description of each column’s data type. This information needs to be manually written down when developing each model, and with thousands of models across different lines of businesses, the description section of the documentation is often omitted. This omission can be confusing for business users who are not familiar with the data when viewing our dbt documentation website. However, documentation in the data engineering world is often regarded as a “necessary evil” — crucial for data integrity, compliance, and collaboration, yet burdened by manual processes that are slow and error-prone. As data models continually evolve, the task of keeping documentation up to date becomes increasingly arduous, often leading to “documentation debt.”
To address these challenges, dbt documentor emerges as a transformative tool that combines the capabilities of traditional dbt documentation and LLMs. This innovative approach automates the otherwise cumbersome workflow and utilizes relation information generated by dbt, eliminating the need to manually cross-reference multiple files and metadata, thereby streamlining the entire documentation process.
Architecture
At Loblaw Digital, our Business Intelligence dbt repo closely resembles a typical dbt project, consisting of project level folders containing models from different teams, along with the configuration files. We wanted to make the process of documentation more efficient.
Leveraging on the ML platform, like Vertex AI, the dbt documentor ingests the dbt model schema directly from a manifest.json file. From there, the LLMs generate comprehensive documentation, detailing everything from describing the SQL queries to the intricate dependencies between models and columns. Importantly, this is achieved without reading actual data, thereby ensuring that the integrity and security of the data remain intact.
