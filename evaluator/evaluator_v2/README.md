# Вероятностный оценщик ТЗ

Откройте `evaluate_tz.ipynb`, установите зависимости первой ячейкой и задайте `TZ_PATH`
для документа из `evaluator/TZ`. Поддерживаются TXT, MD, DOCX (включая таблицы), текстовые
PDF; для сканов сначала нужен OCR. ZIP нужно распаковать, DOC преобразовать в DOCX.
Текст не обрезается: превышение `MAX_SPEC_CHARS` вызывает понятную ошибку.

Ключ ChatGPT задаётся как `OPENAI_API_KEY` в `.env` в корне репозитория, `evaluator`
или `evaluator/evaluator_v2`. Ближайший файл имеет приоритет; существующие переменные
окружения сохраняются. Модель — `OPENAI_LLM_MODEL` (по умолчанию `gpt-4.1-mini`).
ТЗ отправляется в OpenAI API. Ключи и ответы с документами не коммитятся.

Алгоритм использует `chatbots_menu.csv` (фактическое имя файла в коммите b86d175).
Для каждого пакета компонентов передаётся полное ТЗ и критерии меню. ChatGPT возвращает
признак наличия информации, распределение, цитату, комментарий и один вопрос.
Python проверяет ID, вероятности и наличие цитаты в ТЗ. Если информации нет или её
недостаточно для содержательной оценки, Python подставляет prior меню независимо от
предложенного моделью распределения. Однозначный уровень даёт точечное распределение;
частичные/противоречивые данные — распределение между возможными уровнями.
Неизвестный prior: `[0.50, 0.30, 0.15, 0.05]`; неизвестная стоимость уточнения: `2`.
Некорректные значения не заменяются значениями по умолчанию.

Метрики рассчитываются Python строго по `metodology.pdf`:

- `d = k × [0, 1, 3, 10]`;
- `Expected Effort = Σ pᵢdᵢ`;
- `Uncertainty = √Σ pᵢ(dᵢ − Expected Effort)²`;
- `Raw Priority = Uncertainty`;
- `Priority = Uncertainty / √c`.

CSV содержит ровно девять запрошенных столбцов, UTF-8 с BOM и сортировку Priority
по убыванию. Путь: `results/<имя ТЗ>_оценка_v2.csv`. Распределение записывается как
JSON-массив в одной ячейке. Числа не округляются при сохранении. При нулевой
неопределённости вопрос пустой. Ошибки API, отказы модели и некорректные ответы
останавливают расчёт, не маскируются prior и не сохраняют частичный отчёт.
Если JSON-ответ не проходит Pydantic-валидацию, выполняются до трёх попыток
для текущего пакета с указанием полей и причин ошибки. Например, смешанное
распределение с меткой `explicit` должно быть обоснованно исправлено моделью:
при оставшейся неопределённости нужна метка `partial`, а не искусственное
округление вероятностей. Если исправить ответ не удалось, расчёт останавливается
с краткой ошибкой. Ошибки соединения и отказы модели этот механизм не повторяет;
сетевые повторы остаются под управлением OpenAI SDK.

Ноутбук показывает прогресс, все оценки, ожидаемые суммарные затраты, ранжированный
топ вопросов и общее заключение ChatGPT; заключение также сохраняется в Markdown.
Снимаемая неопределённость для вопроса равна U **при предположении полного выяснения
уровня**. Это потенциальное снижение разброса, не гарантированная экономия труда.
Вероятности — экспертные оценки модели, не статистически откалиброванные значения.
Стандартные отклонения нельзя просто складывать; общая неопределённость проекта
без допущений о зависимостях компонентов не рассчитывается.
После получения ответов обновите ТЗ и повторите оценку для нового рейтинга.

Проверка без API (из корня репозитория):

```bash
python -m unittest discover -s evaluator/evaluator_v2 -p 'test_*.py' -v
```

Примечание: в числовом примере раздела 9 PDF при `p=[0.5,0.3,0.1,0.1]`,
`k=3` указано `U≈9.1`; по приведённой там формуле `U=√77.76≈8.818`.
Реализация и тест следуют формуле.
